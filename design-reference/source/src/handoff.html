البنية المقترحة

  • واجهة: Next.js (App Router) مع SSR لصفحات المحتوى (SEO) وnext-intl للعربية/الإنجليزية/الإندونيسية.
  • تنسيق: التوكنز الموجودة في assets/bt.css تتحول إلى CSS variables أو Tailwind theme دون تغيير القيم.
  • الخريطة: MapLibre GL JS بطبقة قمر صناعي ونمط مخصص، ونقاط من API الإدارة (انظر قسم الخريطة).
  • الخلفية واللوحة: أي CMS/Backend يدعم الأدوار (مثل Laravel + Filament أو Strapi)، ببوابة دفع تُحدد بعد السجل التجاري.
  • النموذج الحالي مكتوب HTML/CSS/JS بلا إطار ليكون مرجعًا بصريًا وسلوكيًا مستقلًا. الملفات: assets/bt.js (المكونات المشتركة)، assets/booking.js (التقويم والعداد)، assets/data.js (البيانات التجريبية).

التسعير وقواعد الإضافات

total = packageCost + Σ addonCost + driverCost
packageCost = pkg.pricing == "per_group"
  ? ceil(people / pkg.group_max) * pkg.price
  : people * pkg.price
addonCost(a, qty) = a.pricing == "per_person" ? a.price * people
                  : a.pricing == "per_qty"    ? a.price * min(qty, a.max_qty)
                  : a.price                    // per_booking
driverCost = vehicleFor(people).price_per_day * days   // days = 1 for single-day activities
vehicleFor(n) = n <= 4 ? "sedan" : n <= 7 ? "suv" : "van"
  • إضافة موجودة في pkg.includes_addons → تظهر «مشمولة في باقتك» مقفلة، ولا تُحسب.
  • only_packages لا تشمل الباقة المختارة → معطّلة مع السبب.
  • requires_addon_id غير مختار → معطّلة؛ وإلغاء الشرط يلغي التابعة تلقائيًا.
  • تغيير الباقة يعيد تقييم كل الإضافات ويحدث السعر فورًا مع حركة bump.
  • السعر المعروض قبل الدفع = المبلغ المخصوم. لا رسوم مخفية. أي خصم يظهر في «رحلتي» قبل الدفع.
  • الحجز لا يُرسل دون: تاريخ، وقت (للأنشطة)، وعدد أفراد. الأخطاء تظهر تحت كل حقل ويُمرر للأول.

حالات الحجز والدفع

الدفع:

pending→processing→paid|failed|awaiting_transfer→paid

عنصر الحجز:

created→sent_to_provider→confirmed→completed·cancel_requested→cancelled→refunded
  • «مؤكد» يُعرض فقط عند confirmed من المزود، وليس عند paid.
  • إعادة محاولة الدفع تستخدم نفس Order.id (idempotency key) فلا يتكرر الطلب.
  • المنتجات الرقمية (الجدول والخريطة) تصبح completed فور paid.
  • كل تغيير حالة يُسجّل في Timeline ويرسل إشعارًا (بريد + واتساب) إذا اختار المسؤول ذلك.

الخريطة: مستويات التنفيذ

المرحلة الأولىأساسي — خريطة مخصصةMapLibre + طبقة قمر صناعي (مثل MapTiler Satellite) بتدرج ألوان الهوية، علامات ببطاقات زجاجية، تجميع حسب الزوم (مناطق ← أماكن ← بطاقات)، فلاتر، الأقرب مني، منطقة مجانية بقناع Blur خارجها.
بعد الإطلاقمتقدم — 3Dتفعيل terrain وpitch وانتقالات flyTo، علامات قائمة. لا يَعِد بمجسمات لكل مبنى.
استعراضي — بعد دراسةجولة افتراضيةمسار متحرك بسيارة/شخصية على طرق حقيقية. يحتاج بيانات طرق وتكلفة رسوميات؛ معروض في النموذج كمفهوم فقط.
  • تفاعلات: flyTo(region) ٨٥٠ms، تحديث النتائج حسب حدود الشاشة بعد توقف السحب (debounce ١٨٠ms)، النقر على نقطة يفتح بطاقة جانبية/Bottom Sheet ولا يغادر الصفحة، وصفحة تفاصيل المكان مستقلة.
  • الأماكن خارج المنطقة المجانية تُرسل من الخادم بدون اسم أو صور أو إحداثيات دقيقة حتى يملك المستخدم MapAccess (حماية فعلية لا تكتفي بإخفاء الواجهة).
  • «الأقرب مني» يطلب الإذن بعد شرح، ولا يحفظ الموقع.

الوصول والأداء

  • تباين النص ≥ 4.5:1 (انظر Design System). البرتقالي لا يحمل نصًا أبيض.
  • كل عنصر تفاعلي button أو a حقيقي، بحجم لمس ≥ 44px، وحلقة تركيز ظاهرة.
  • الخريطة: role="application" + تحكم بالأسهم و+/−، والنتائج متاحة كقائمة نصية بجانبها.
  • رسائل الأخطاء والنتائج ضمن aria-live. Modals تحصر التركيز وتغلق بـ Esc.
  • الصور: loading="lazy" لما تحت الطية، وsrcset بأحجام 480/960/1600 بصيغة WebP/AVIF في الإنتاج.
  • ميزانية: LCP < 2.5s على 4G، الخريطة تُحمّل عند الحاجة (dynamic import)، وخطوط Noor بـ font-display: swap وsubset.

اللغات والاتجاه

  • العربية افتراضية RTL، الإنجليزية LTR، الإندونيسية للموقع العام فقط (حسب الاعتماد). لوحة التحكم عربي/إنجليزي.
  • كل المحتوى القابل للترجمة حقول لكل لغة في الكيانات (title.ar/en/id)؛ صفحة بلا ترجمة تعرض العربية مع تنبيه.
  • CSS بخصائص منطقية فقط؛ الأسهم الاتجاهية تُعكس؛ الأرقام والأسعار والهواتف dir="ltr".
  • الروابط تحمل اللغة: /ar/…، /en/…، مع hreflang.
