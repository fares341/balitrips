# الدفعة 5 — إصلاح الميزات الموجودة لتطابق الوثيقة + تجهيز الإنتاج

مراجعة كاملة للكود مقابل `الوثيقة التفصيلية` و`العقد`، ثم إصلاح كل ميزة موجودة كانت
تعمل خطأً أو ناقصة عمّا تطلبه الوثيقة. الميزات الجديدة كلياً (الدخول بالجوال، موافقة
الإدارة على الجهاز…) في قائمة "لم يُنفَّذ بعد" أسفل الملف.

## التشغيل

```bash
pnpm install
pnpm db:migrate          # drizzle/0008_production_fixes.sql
pnpm db:seed             # على قاعدة جديدة فقط: المناطق، التصنيفات، الوسوم
pnpm format && pnpm typecheck && pnpm lint && pnpm test
```

> كُتبت هذه الدفعة في بيئة بلا وصول إلى npm، فلم يُشغَّل `typecheck` ولا الاختبارات.
> الهجرة طُبّقت فعلاً على Postgres 16 (قاعدة جديدة + قاعدة قائمة). شغّل الأوامر أعلاه
> وأرسل أي خطأ.

## أمان (حرج)

| المشكلة | الإصلاح |
|---|---|
| أسرار الإنتاج داخل المشروع (`.env.production`, `app.env`, `postgres.env`, `.env`) و`bali_db_dump.sql` (hash كلمة مرور المدير + 9 جلسات) يُنسخ داخل صورة الـ worker | حُذفت من المشروع. `.env.production.example` بلا أسرار. `/*.sql` في `.gitignore` و`.dockerignore`. **غيّر كل الأسرار على الخادم** — اعتبرها مكشوفة. |
| `/api/places/search` يكشف الأماكن المقفلة: معرّفها + فلترة النص/الموقع عليها → إعادة بناء الاسم والإحداثيات | النص والموقع لا يُطبَّقان على المقفل أبداً، ولا يُعاد بمعرّف. عدد فقط على الفلاتر العامة. |
| فتح `/file` مباشرة يعطي PDF كاملاً متجاوزاً "عرض فقط" وحد التحميل | `/file` يقبل جلب العارض فقط (`x-bt-viewer` + `Sec-Fetch-Dest`)، ويُرجع `octet-stream`. التنقل المباشر يُسجَّل `unauthorized_access` ويُحوَّل للعارض. |
| سياسة الجهاز الجديد وحد الأجهزة من Studio لا تُطبَّق عند الدخول (env فقط) | `registerSignInDevice` يقرأ إعدادات Studio. |
| 2FA للمدير معطّل والدفع الوهمي مفعّل في ملفات الإنتاج | `LIVE_MODE=true` يتجاهل `DISABLE_ADMIN_2FA` و`ALLOW_SANDBOX_PAYMENTS` مهما كانت قيمتهما (`src/lib/live-mode.ts`). تحذيرات في لوحة التحكم وعند تشغيل الـ worker. |
| أعمدة المال int32 → ينهار عند 21.4 مليون روبية (≈ 1,300$) | كل أعمدة `*_minor` إلى `bigint` (`mode: 'number'`). |
| حظر الجهاز/IP لا يُطبَّق على المفضلة ورحلتي والفواتير والدفع | `requireActiveUser()` / `activeUserOrNull()` (`src/lib/security/require.ts`) في كل صفحات الحساب وإجراءاته وفي الدفع. رسالة واضحة في `/account?blocked=…`. |
| مصدر IP غير موحّد (Better Auth / الحارس / الإدارة)؛ خلف Cloudflare يصبح الكل عنواناً واحداً | `TRUSTED_IP_HEADER` يُطبَّق في Better Auth أيضاً، ومحلّل واحد للإدارة. شرح Cloudflare في `caddy/Caddyfile`. |

## الخريطة والبحث والمناطق

- **المناطق والأحياء (الوثيقة 7):** حقول جديدة في `regions`: وصف، حالة، منطقة أم، مركز
  ونصف قطر تقريبي. أُضيفت Kuta, Seminyak, Canggu, Uluwatu, Nusa Dua, Sanur (جنوب) وUbud (وسط).
  فلترة "جنوب بالي" تشمل أحياءها. إدارتها من Studio → Taxonomy.
- **التصنيفات (6.2، 10.1):** وصف وحالة، وأُضيفت: أنشطة، أماكن سياحية، أسواق، تسوق،
  فعاليات، مستشفيات. أماكن الـ seed مربوطة بتصنيفاتها.
- **الوسوم:** كانت فارغة في أي تنصيب جديد (الهجرة 0006 تنقل من أماكن قبل الـ seed).
  الـ seed يكتب `place_tags` الآن، والوسوم القديمة لها ترجمات حقيقية. أزرار الوسوم في
  الخريطة من قاعدة البيانات لا قائمة ثابتة.
- **البحث:** "ar"/"en" كان يطابق كل صف (بحث داخل مفاتيح JSON) — أُصلح. توحيد الحروف
  العربية (أ/إ/آ، ة/ه، ى/ي، التشكيل). "Cafes in Kuta" / "كافيهات في كوتا" تُفهم.
  الوسوم والمناطق المعطّلة لا تُقترح.
- **لوحة المكان:** المنطقة، الوصف التفصيلي، الفيديوهات (YouTube/Vimeo/mp4 بروابط https
  فقط)، أسماء الوسوم المترجمة. حالة "محفوظ" الحقيقية (كان الضغط على مكان محفوظ يحذفه بصمت).

## المفضلة ورحلتي

- "أضف لرحلتي" في المفضلة كان يضع المكان في **السلة** كبند بصفر — الآن إلى "رحلتي".
- المفضلة تعرض التصنيف + المنطقة، والأماكن المخفية لا تظهر.
- ترتيب رحلتي: الأسهم كانت تحرّك عنصراً آخر بعد تعيين الأيام. التحريك الآن داخل اليوم.
- الأماكن المسودة/المخفية لا تظهر في رحلتي.

## الجداول والباقات

- حقول الوثيقة 4.2: وصف تفصيلي، معرض صور، "يشمل الخريطة؟"، VIP، ملاحظات داخلية،
  أماكن مرتبطة. تظهر في صفحة الجدول.
- **رفع PDF جاهز للجدول** لكل لغة من Studio؛ يُسلَّم بدل المولّد تلقائياً بنفس الحماية.
- جدول "يشمل الخريطة" يمنح الوصول للخريطة عند الدفع (VIP إن كان جدول VIP).
- الباقة: صلاحية "تحميل PDF" (إيقافها = عرض فقط). تجديد الباقة قبل انتهائها يُمدّ المدة.

## الطلب المخصص (الوثيقة 5)

- الحالات حرفياً كما في الوثيقة: جديد، تحت المراجعة، قيد التنفيذ، **بانتظار رد العميل**،
  مكتمل، **ملغي** (الهجرة تنقل القديمة).
- النموذج: المناطق المفضلة، نوع رحلة **فاخرة / اقتصادية**، مطاعم فاخرة، مغامرة.
- اكتمال الطلب يرسل إشعاراً + بريداً + **واتساب** (قالب `bali_custom_completed`، معامل `name`).

## سجل النشاط والإشعارات

- يُسجَّل الآن ما كان معرّفاً ولا يُستدعى: مشاهدة مكان، تغيير كلمة المرور، الشراء، تحديث الطلبات.
- رسالة الترحيب عند التسجيل تُرسل (القالب كان موجوداً ولا شيء يضعه في الطابور).
- سياسة "warn": المستخدم يرى إشعار تجاوز حد الأجهزة مع اقتراح الترقية.
- تنبيه للإدارة عند دخول مستخدم مدفوع من جهاز جديد (الوثيقة 4.3).
- "آخر عمليات تسجيل الدخول" في صفحة أجهزتي (الوثيقة 3.3).

## لوحة التحكم

- الإحصائيات (الوثيقة): المستخدمون، الجداول المباعة، مستخدمو الخريطة، أكثر الأماكن مشاهدة
  وحفظاً، أحدث المستخدمين، التنبيهات الأمنية المفتوحة، وتحذيرات إعداد الإنتاج.
- تعديل بيانات العميل (الاسم، البريد، الجوال، الدولة) — تغيير البريد ينهي الجلسات.

## أخرى

- Stripe: `expires_at` كان على الحد الأدنى بالضبط (30 د) فيُرفض مع أي تأخير → 35 د
  (حجز السعة ساعة).
- `update-user` في Better Auth كان يقبل قيماً طويلة لـ locale/phone/country (خطأ 500).
- `deploy/Caddyfile` كان متأخراً عن `caddy/Caddyfile` (CSP بدون Stripe) — مُزامَن.
- `Permissions-Policy` يسمح بمشغّلات الفيديو المضمّنة.

## قوالب واتساب جديدة

`bali_custom_completed` ({{1}} = الاسم). القوالب الأخرى كما في الدفعة 4.

## لم يُنفَّذ بعد (ميزات جديدة — الخطوة التالية)

- التسجيل والدخول برقم الجوال + التحقق.
- سياسة "موافقة الإدارة على الجهاز الجديد".
- الباقة العائلية (أكثر من مستخدم).
- إرسال إشعار يدوي من الإدارة لمستخدم/للكل.
- تتبع الصفحات المزارة، والموقع التقريبي (GeoIP) للدخول.
- صفحة إدارية لكل الأجهزة، وتفعيل/تعطيل الحساب منفصلاً عن الحظر.
- كروت نتائج البحث داخل الخريطة (الصورة/المسافة/الأزرار) وتجميع الدبابيس بعدد.
- رفع فيديو (حالياً روابط)، ومعرض صور للمكان، وسحب وإفلات في رحلتي.
- قائمة مدفوعات منفصلة وإصدار إيصال يدوي.
